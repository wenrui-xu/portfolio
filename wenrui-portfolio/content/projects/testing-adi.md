## Overview

This case study focuses on the testing work around ADI rather than presenting it as a separate shipped application.

## My role

I prepared tasks for participants, collected observations and translated recurring problems into changes for the Android app.

## Challenges

### Problem

Some task and routine behaviors seemed clear in implementation but proved confusing during use.

### Why

Voice controls, repeated subtasks and navigation involve multiple steps that are easy to miss when testing only as the developer.

### Solution

I used user sessions and a feedback form to identify the specific interactions that needed clearer behavior or language.

### Result

The findings helped prioritize changes to voice affordances, recurring tasks and back navigation. A public bug-report gallery will be added after the materials are ready to share.

## Process

Test preparation, observation, issue review and implementation feedback formed a practical QA loop.

## Testing results

The available evidence is qualitative user feedback. This page does not claim performance gains or defect counts that have not been measured.
